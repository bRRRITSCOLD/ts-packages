# Can CI read a Penpot library file without a browser tab?

Research for [#18](https://github.com/bRRRITSCOLD/ts-packages/issues/18). Gathered 2026-11-03.

Sources: the `penpot/penpot` repo at tag [`2.18.5`](https://github.com/penpot/penpot/tree/2.18.5) (commit `f4456696`, 2026-10-26) and at `develop` (commit [`4173cc34`](https://github.com/penpot/penpot/tree/4173cc34ab85e0470fe1cbba3e2e24dfa0477d05), 2026-11-03), its `CHANGES.md`, `docs/technical-guide`, the API docs page served by the instance (`/api/main/doc`), and a live self-hosted Penpot 2.18.5 (images `penpotapp/backend:2.18.5`; the frontend's `version.txt` reports `2.18.5-RC1`). Links to `2.18.5` carry line numbers from that tag.

**Legend:** **V** = verified, either live against the 2.18.5 instance (the command is given) or in the linked source. **C** = corroborated by a doc or changelog but not exercised. **U** = unverified (inferred or not tested).

## Live test, in short

On the throwaway instance I registered a fresh profile over RPC (`prepare-register-profile` then `register-profile`), logged in with `login-with-password`, created an access token, imported `Library.penpot` into that profile's default project with `import-binfile`, and read it back three ways: `get-file` as JSON, `get-file` as transit, and `export-binfile` (then downloaded the zip). No other account's files were touched. The token and password were never printed and are not in this file.

| What the drift check needs | `get-file` (JSON) | `get-file` (transit) | `export-binfile` zip |
|---|---|---|---|
| Component names and paths (26) | V | V | V |
| `variantProperties` per variant component (20) | V | V | V |
| Variant set name (the container shape, `isVariantContainer`) | V, in `data.pagesIndex[*].objects` | V | V, in `pages/<page>/<shape>.json` |
| `sharedPluginData` `brrritscold.core-react` / `link` (25 components) | **V but the key is mangled** to `brrritscoldCoreReact` | V, exact key `:shared/brrritscold.core-react` | V, exact key `"shared/brrritscold.core-react"` |
| Token catalog (sets, tokens, `$themes`, `$metadata`) | V, DTCG multi-set, byte-for-byte equal to the export's `tokens.json` | V, but as Penpot's internal `#penpot/tokens-lib` structure, not DTCG | V, `tokens.json` |
| Round trip | n/a | n/a | V, components and `tokens.json` identical to the original export |

## 1. Which RPC commands return file data

All commands are `POST /api/rpc/command/<name>` (the API docs also list `/api/main/methods/<name>`, which works too: V, `GET /api/main/methods/get-profile` returned the profile). Methods named `get-*` also accept `GET`. Requests and responses can be `application/json` or `application/transit+json`; transit is the default when `Accept` is absent ([API doc page, "Content Negotiation"](http://localhost:9001/api/main/doc), V; [middleware.clj#L165-L200](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/http/middleware.clj#L165-L200), V).

### `get-file`: the whole file in one response

- Params `{id, features?}`; result is the `file` row plus `data` and `permissions` ([files.clj#L120-L222](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/rpc/commands/files.clj#L120-L222)). Auth: a logged-in profile with read permission on the file; viewers qualify. **V** (source and live: 200, about 240 KB for this library).
- `data` holds `components`, `pagesIndex` (pages with `objects`), `pages`, `tokensLib`, `options` and, when present, `pluginData`. **V** live.
- **Fragmentation does not reach the client unless it asks for it.** If the stored file has `fdata/pointer-map` or `fdata/objects-map` and the request's `features` does not list them, the backend realizes pointers and converts objects maps to plain maps before responding ([files.clj#L201-L222](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/rpc/commands/files.clj#L203-L220)). The client-feature check is skipped when `features` is absent ([features.cljc#L183-L202](https://github.com/penpot/penpot/blob/2.18.5/common/src/app/common/features.cljc#L183-L202)). **V** in source; live, the imported file gained `fdata/objects-map` (a default flag) and the JSON response still had plain `objects` maps. So CI should **not** send `features`, and never needs `get-file-fragment`.
- `get-file-fragment {file-id, fragment-id}` returns one pointer-map fragment ([files.clj#L224-L270](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/rpc/commands/files.clj#L224-L270)). Only needed by clients that declare `fdata/pointer-map`. **V** in source, not exercised.
- The storage backend for file data (`PENPOT_FILE_DATA_BACKEND`: `db`, `legacy-db` or `storage`; this instance uses `legacy-db`) is resolved server-side and is invisible to RPC callers ([fdata.clj#L85-L105](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/features/fdata.clj#L85-L105), [config.clj#L55](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/config.clj#L55)). **V** in source; the response carries `"backend": "legacy-db"`.
- `get-file` runs pending data migrations on read and returns the file's data `version` (67 here) and `migrations` list. **V** live.

#### The JSON encoding mangles plugin-data namespaces

The JSON writer camel-cases every keyword key with `cuerdas` `str/camel`, which drops the keyword's namespace ([json.cljc#L29-L33](https://github.com/penpot/penpot/blob/2.18.5/common/src/app/common/json.cljc#L29-L33), [middleware.clj#L150-L157](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/http/middleware.clj#L150-L157)). Shared plugin data is stored under the keyword `:shared/<namespace>` and private plugin data under `:plugin/<plugin-id>` ([library.cljs#L858-L900](https://github.com/penpot/penpot/blob/2.18.5/frontend/src/app/plugins/library.cljs#L858-L900)). So in JSON, `:shared/brrritscold.core-react` arrives as `brrritscoldCoreReact`: the `shared/` marker is gone and `.`/`-` are folded. **V** live. The inner key (`link`, a string) and the value are untouched. Transit keeps the exact keyword (**V** live, decoded with `transit-js@0.8.874` in Node 25).

### `export-binfile`: the `.penpot` zip

- Params at 2.18.5: `{file-id, include-libraries, embed-assets}`, all required ([binfile.clj#L40-L80](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/rpc/commands/binfile.clj#L40-L80)). Auth: read permission on the file. **V**.
- The response is an SSE stream (always transit-encoded, whatever `Accept` says, per the API doc page). The final `end` event carries `{"~#uri": "<public-uri>/assets/by-id/<uuid>"}`; that URL serves the zip for 60 minutes and needs the same auth (anonymous download: 401). **V** live.
- The zip is the binfile v3 layout: `manifest.json` (`"version": 1`, `generatedBy`, per-file `features`), `files/<id>.json`, `files/<id>/components/<id>.json` (with `variantId`, `variantProperties`, `pluginData`), `files/<id>/pages/<page>/<shape>.json`, `files/<id>/tokens.json`. Plugin-data keys keep the `shared/` prefix because v3 encodes with schema-driven JSON transformers, not the RPC camel-caser ([v3.clj#L102-L127](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/binfile/v3.clj#L102-L127)). **V** live.
- `import-binfile` (multipart `file` or chunked `upload-id`, SSE response) imported the 370 KB library into a new file id with no loss: all 26 components (path, name, `variantProperties`, `pluginData`) and `tokens.json` matched the original export after re-export. **V** live.

### On `develop` (unreleased)

- `get-file-tokens {file-id}` returns the tokens as a DTCG document, and `get-file-plugin-data {id, namespace?}` returns **file-level** plugin data only, not component-level. Both are marked `::doc/added "2.20"` ([files.clj@develop#L735-L780](https://github.com/penpot/penpot/blob/4173cc34ab85e0470fe1cbba3e2e24dfa0477d05/backend/src/app/rpc/commands/files.clj#L735-L780)). **V** in source. `get-file-plugin-data` does not cover the drift check, which needs component plugin data.
- `export-binfile` gains an optional `type` (`include-libraries`, `merge-libraries`, `detach-libraries`, `link-later`) and makes `include-libraries` / `embed-assets` optional and deprecated ("2.19") ([binfile.clj@develop#L40-L80](https://github.com/penpot/penpot/blob/4173cc34ab85e0470fe1cbba3e2e24dfa0477d05/backend/src/app/rpc/commands/binfile.clj#L40-L80)). **V** in source.
- 2.19.0 "Enable closed schemas for RPC method parameters" ([#11136](https://github.com/penpot/penpot/pull/11136)): unknown params will be rejected, so CI must send only declared params. **C** (changelog, not checked in code).

## 2. How CI authenticates

- **Personal access tokens.** `create-access-token {name, expiration?}` (session-authenticated) returns a JWT once; `get-access-tokens` never returns it again for non-MCP tokens ([access_token.clj#L31-L104](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/rpc/commands/access_token.clj#L31-L104)). **V** in source and live. `expiration` is an ISO-8601 duration **without** the `PT` prefix, e.g. `"720h"`; `"30d"` is rejected ([time.cljc#L160-L174](https://github.com/penpot/penpot/blob/2.18.5/common/src/app/common/time.cljc#L160-L174)). **V** live. Omitting it means no expiry. The UI offers Never, 30, 60, 90 or 180 days ([integration.md#L63-L101](https://github.com/penpot/penpot/blob/2.18.5/docs/technical-guide/integration.md#L63-L101)). **C**.
- **Header:** `Authorization: Token <jwt>` (`Bearer` is parsed as a session token, not an access token) ([middleware.clj#L277-L290](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/http/middleware.clj#L277-L290)). **V** in source.
- **The backend flag `enable-access-tokens` is required and is not a default flag** ([flags.cljc#L186-L216](https://github.com/penpot/penpot/blob/2.18.5/common/src/app/common/flags.cljc#L186-L216), [http/access_token.clj#L61-L65](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/http/access_token.clj#L61-L65), [configuration.md#L696](https://github.com/penpot/penpot/blob/2.18.5/docs/technical-guide/configuration.md#L696)). **V** in source and live: the test instance's backend `PENPOT_FLAGS` lacks it, `create-access-token` still succeeded, but every request with the token was treated as **anonymous** (`get-profile` returned "Anonymous User", `get-projects` returned `authentication-required`). I did not change the cluster, so **an RPC read authenticated by the token is U**; the reads above used the session cookie from `login-with-password`. Both paths set the same `profile-id` before the handler runs ([rpc.clj#L95-L130](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/rpc.clj#L95-L130)), so the data returned is the same (**V** in source).
- **Scopes:** none in the public API. Tokens are created with empty `perms`; `perms` only gate elevated operator methods (granted by SQL or REPL). A token otherwise has the full power of its profile ([access_token.clj#L25-L34](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/rpc/commands/access_token.clj#L25-L34), [rpc.clj#L163-L197](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/rpc.clj#L163-L197)). **V** in source. To limit blast radius, give CI a dedicated profile with the **viewer** role on the library's team; `get-file` and `export-binfile` only check read permission. **V** in source.
- **Fallback without the flag:** a CI job can log in with `login-with-password` and use the `auth-token` cookie. **V** live. Worse: a stored password, the session TTL, and it breaks under SSO-only setups.
- **MCP keys do not work.** Since 2.18.0, MCP tokens are minted with issuer `urn:penpot:mcp-token`, and `decode-token` accepts only `access-token` ([CHANGES.md 2.18.0](https://github.com/penpot/penpot/blob/2.18.5/CHANGES.md), "Fix MCP tokens being usable as API access tokens", [#10962](https://github.com/penpot/penpot/pull/10962); [http/access_token.clj#L17-L24](https://github.com/penpot/penpot/blob/2.18.5/backend/src/app/http/access_token.clj#L17-L24)). **V** in source. Also, creating a new MCP token deletes the profile's other MCP tokens. MCP tokens minted before 2.18.0 carried the old issuer and are not rejected by type in `wrap-authz`, so they may still authenticate until rotated. **U** (inferred from source, not tested). Do not rely on MCP keys either way.

## 3. Format stability

- **RPC/transit:** undocumented beyond the auto-generated `/api/main/doc` page and an OpenAPI rendering. Methods carry `::doc/added` and `::doc/changes` entries but there is no API version. The `data` payload is Penpot's internal data model and changes whenever the data model does. **V**.
- **Data migrations** (each changes stored data shape or semantics) available per release, counted from `available-migrations` in [migrations.cljc](https://github.com/penpot/penpot/blob/2.18.5/common/src/app/common/files/migrations.cljc): 2.13.0 = 72, 2.14.0 = 73, 2.15.0 = 73, 2.16.0 = 78, 2.17.0 = 79, 2.18.0 to 2.18.5 = 81, develop = 89. **V** (regex count; approximate). Most recent ones fix paths, strokes, blur and text; several touch tokens (2.17 DTCG `$` discriminator [#9912](https://github.com/penpot/penpot/pull/9912), clashing-name migration reverted [#9950](https://github.com/penpot/penpot/pull/9950)) and variants (develop "Fix repair bad variants" [#11983](https://github.com/penpot/penpot/pull/11983)). **V** (commit history).
- **Binfile v3:** documented since July 2026 in [penpot-file-format.md](https://github.com/penpot/penpot/blob/2.18.5/docs/technical-guide/developer/data-model/penpot-file-format.md) ([#10674](https://github.com/penpot/penpot/pull/10674)). `manifest.version` is `1` and has not changed; binfile `v3` has been the only export since 2.12 (`export-binfile` "Remove version parameter, only one version is supported"). **V**. But the doc is **incomplete and partly wrong** for our needs: its component table omits `variantId` / `variantProperties`, its `tokens.json` example (`sets` / `themes` / `activeThemes`) does not match the real DTCG multi-set file (`<set>` / `$themes` / `$metadata`), and it describes plugin-data keys as plugin ids without the `shared/` prefix. **V** (doc vs live export). Treat the doc as orientation, the live export as the contract.
- **Binfile churn 2.13 to develop:** `v3.clj` changes were mostly import hardening (zip limits, timeouts, SVG sanitizing). Content-affecting ones: tokens status added to import ([#11850](https://github.com/penpot/penpot/pull/11850), 2.18), token libraries handled on export ([#12077](https://github.com/penpot/penpot/pull/12077), develop), export types and durable jobs ([#12056](https://github.com/penpot/penpot/pull/12056), develop). **V** (commit history); effect on the zip layout **U** until 2.19 ships.

## 4. Alternative: a headless browser tab running the MCP plugin

What it would take (**C** from [mcp/README.md](https://github.com/penpot/penpot/blob/2.18.5/mcp/README.md) and [mcp/docs/multi-user-mode.md](https://github.com/penpot/penpot/blob/2.18.5/mcp/docs/multi-user-mode.md); nothing here was run):

1. Playwright launches Chromium, logs into Penpot (form or `login-with-password` cookie), opens the workspace URL of the library file.
2. Load the MCP plugin from its manifest URL through the Plugins menu, open its UI, click "Connect to MCP server". The README warns not to close the plugin UI and to keep the tab active, since browsers suspend inactive tabs.
3. An MCP client in the same job calls `execute_code` with Plugin-API code (`library.local.components`, `component.getSharedPluginData(...)`, `variantProps`, tokens).

Fragility: UI selectors for the plugin menu and connect button are not a contract; workspace load needs the WebGL/wasm renderer (`render-wasm` is a default feature flag) to come up headless; Chromium 142+ private-network-access prompts block localhost connections unless pre-allowed; multi-user/remote MCP mode is "under development … for testing purposes only" with a token hard-coded in the plugin; and it adds a browser, the MCP server and the plugin server to every CI run. It does give the Plugin API's stable, documented, typed view of components, variants, plugin data and tokens. **U** that it runs reliably headless.

## Recommendation for the drift check

**Read the library with `export-binfile` over the RPC API, authenticated by a personal access token of a dedicated viewer-only CI profile, and parse the zip.** Unzip it, read `files/<id>/components/*.json` (`path`, `name`, `variantId`, `variantProperties`, `pluginData["shared/brrritscold.core-react"].link`), the variant container shapes for set names, and `files/<id>/tokens.json` for sets, tokens and `$themes`. That is the format the prototype already parsed, it keeps exact plugin-data keys and DTCG tokens, and it round-tripped losslessly here.

`get-file` with `Accept: application/json` is the simpler one-shot alternative (no SSE, no second download), but only if the parser maps the mangled namespace (`brrritscoldCoreReact`) and you accept that `shared/` and private namespaces become indistinguishable. `get-file` as transit keeps exact keys but returns tokens in Penpot's internal structure. On 2.20+, `get-file-tokens` can replace the token part.

Risks:

- **Server config:** the backend needs `enable-access-tokens` in `PENPOT_FLAGS`. Without it, tokens are silently ignored and requests run anonymous. The drift check should fail loudly on `authentication-required` or an "Anonymous User" profile.
- **Token power:** no scopes. A leaked token acts as the CI profile, so keep that profile viewer-only on one team and set an expiry (rotation becomes a chore).
- **Format drift:** neither the RPC payload nor the zip has a compatibility promise, and the published file-format doc already lags reality. Pin the Penpot version the check is tested against, validate the parsed shape with a schema, and fail with a clear "format changed" message instead of reporting false drift. Re-run against each Penpot minor (2.19 changes `export-binfile` params and closes RPC param schemas).
- **SSE parsing:** the export stream is transit-encoded even with `Accept: application/json`; the CI client only needs the `end` event's `~#uri` value.
- **Untested here:** the token-authenticated read itself (blocked by the instance flag). Enable the flag on a test instance and repeat `get-file` / `export-binfile` with `Authorization: Token` before building on it.
