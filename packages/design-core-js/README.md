# @brrritscold/design-core-js

The component link between the design system library and `core-react`, as pure code: the resolver, the exceptions-record, library-snapshot and token-file schemas, the drift check's rule engine and its coverage report. Browser + node; Penpot lives only at the edges, so everything here takes normalized shapes, never raw Penpot objects.

**Private.** Not published, ignored by Changesets. Spec: [`docs/design-system/SPEC.md` § C](https://github.com/bRRRITSCOLD/ts-packages/blob/main/docs/design-system/SPEC.md); terms: [`GLOSSARY.md`](https://github.com/bRRRITSCOLD/ts-packages/blob/main/docs/design-system/GLOSSARY.md).

## Tripwire

**A change to a drift rule (rules 1–9, the checked and exempt attributes of rules 7–9), the naming convention or the exceptions record also updates the `design-system` skill in personal-ai.** Agents build `core-react` code from designs by that skill; if it describes rules this package no longer enforces, they build wrong code that the drift check then fails.

## The component link

`resolveComponentLink` (`./component-link`) is the one resolver the drift check, the link inspector and the link reader share, so they can't disagree.

| Library side                                | Code side                                                    |
| ------------------------------------------- | ------------------------------------------------------------ |
| `Components/Button`                         | `Button` from `@brrritscold/core-react`                      |
| `Components/Card/Header` (a compound part)  | `CardHeader`                                                 |
| `icon/Trash2`                               | `Trash2Icon` from `@brrritscold/core-react/icons`            |
| `_internal/Slot` (slot placeholder)         | nothing                                                      |
| variant property `size` = `sm`              | `size="sm"`                                                  |
| variant value `default`                     | prop omitted                                                 |
| variant value `true` / `false`              | boolean                                                      |
| exceptions record `props.disabled.from/map` | `disabled` set from another variant property through the map |
| exceptions record `package`                 | the export is looked up in that package (drift: _unchecked_) |
| exceptions record `slots`                   | roles of parts that are slot placeholders                    |

The exceptions record lives in `sharedPluginData` namespace `brrritscold.core-react`, key `link`, and refers to parts by role, never by layer name.

## Drift rules

`checkDrift` (`./drift-check`) takes the library snapshot, the code manifest and the token file (`tokens.json`, `./token-file`). Library → code is an **error**; code → library is a **coverage gap**.

1. Component name (path stripped) → named export in `.`; a component whose exceptions record names another package is reported **unchecked**.
2. Variant property → prop (a boolean or literal union in the code manifest); value → literal in that union; `default` → the prop is optional; an exceptions value map overrides and must cover every value.
3. Compound parts are copies of library components (a copy of something outside the library fails), so rule 1 covers them. Layout wrappers (plain boards and groups the parts sit in) pass unless one is named like a part export: `Card` + wrapper `Header` with `CardHeader` exported fails, pointing at `Components/Card/Header`.
   Names are exact: component, part, variant property and value spell the export or prop. A failing component or part name (rule 1) or variant property (rule 2) gets `did you mean \`<Name>\`?` when exactly one export or prop matches ignoring case and whitespace (`findNearMiss`, `./component-link`); a failing value lists the prop's literal union. The hint never resolves a link.
4. Components under `icon/` → `<Name>Icon` in `./icons`.
5. The exceptions record is valid against its schema, and every key points at a real prop, variant property, variant value or role.
6. **Token catalog** — the snapshot's token sets and their tokens (type, value, description) equal `tokens.json`, and its themes are `Mode/Light` (`primitive` + `light`) and `Mode/Dark` (`primitive` + `dark`). Reported under `Token catalog`, one error per difference; every message says to re-run token sync.
7. **Unbound** — a layer's `unbound` list isn't empty: a checked attribute holds a raw value.
8. **Unknown token** — an applied token's name isn't in any set of `tokens.json`.
9. **Primitive colour** — a `fill` or `stroke-color` takes a token of the `primitive` set.

Rules 7–9 skip `_internal/` components (the slot placeholder keeps its raw magenta fill), as the resolver links them to no code. They read each component's `layers`, which the snapshot refresh computes from Penpot so the check stays offline. Checked attributes (`CHECKED_TOKEN_ATTRIBUTES`), on every layer of every main component including nested part copies, each only when set to a non-default value: fill, stroke colour, radius `r1`–`r4`, padding `p1`–`p4`, row/column gap, font family/size/weight, letter spacing, shadow, opacity ≠ 1. Exempt: x/y, width/height, stroke width, rotation, margin. Messages name a layer by its name path and id: ``layer `Button / Label` (3f2a…)``. Whether a layer has the _right_ semantic token is left to review.

Coverage gaps: exports with no library component, minus the `allowlist` in `design/drift.config.json`; and literal values of a prop the library sets that no variant uses.

## Token sync

`buildTokenSyncScript` (`./token-sync`) turns `tokens.json` and `design/token-migrations.json` into one self-contained script, run as the body of a Penpot MCP `execute_code` call in the tab of the file to sync. It is pure: it builds a string and never talks to Penpot. Print it with `design-drift token-sync` ([`design-core-node`](https://github.com/bRRRITSCOLD/ts-packages/tree/main/packages/design-core-node)), which also says how an agent runs it.

The script leaves the file's catalog with exactly the sets `primitive`, `light` and `dark` (created in that order) holding exactly the tokens of `tokens.json`, and exactly the themes `Mode/Light` and `Mode/Dark`, activating `Mode/Light` when no `Mode` theme is active. A token that differs is removed and added again. It compares values with `sameToken` (`./token-file`), the function drift rule 6 uses, embedded in the script by its source text, so the sync and the check can't disagree about Penpot's rewritten forms (numbers as strings, font families as a list, shadows as layers with `inset`).

Each migration whose `from` is still in the file (followed through later renames to a token of `tokens.json`) re-applies `to` on every shape whose `shape.tokens` names `from`, on the same properties, on every page; `from` is removed only once no shape applies it, and the shapes that still do are flagged. `to: null` flags every shape applying `from` for a human. The script returns `{ changes, flagged }`; a second run on a synced file returns no changes.

The builder throws, so no script exists, on a token Penpot can't hold: a negative shadow spread (Penpot rejects it) or a CSS-string shadow (stored, never resolved), and on a migration whose `to` never reaches a token of `tokens.json`.
